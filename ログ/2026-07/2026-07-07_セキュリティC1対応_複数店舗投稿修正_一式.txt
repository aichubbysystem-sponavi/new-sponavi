### 注意点・ハマったこと
- system_oauth_tokens は「テーブルではなく VIEW」。定義は
  SELECT access_token,refresh_token,expiry FROM system.tokens t JOIN system.accounts a ... WHERE a.type=1 ...
  → VIEWにはRLSを張れず ERROR 42809。ビューは既定でオーナー権限で動くため下位テーブルのRLSも素通りする。
  対策は「ビューへのSELECT権限を anon/authenticated から REVOKE」。system スキーマはPostgREST未公開のため
  外部到達経路はこのpublicビューのみ＝REVOKEで露出停止。SET ROLE anon → permission denied(42501) で検証済み。
- .env.local のプロジェクトref（rtqvyuscibswachlewks）は古く、DNS解決不可＝存在しない/別プロジェクト。keylen46の新形式キー。
  → ローカルから本番Supabaseのanon検証はできない。本番検証はSupabaseのSQL Editorで SET ROLE anon を使う。
- アプリのトークン取得(gbp-token.ts getOAuthToken/getAllOAuthTokens, oauth-accounts route)は全て getSupabase()=service_role。
  だから anon/authenticated への REVOKE でアプリは壊れない（GBP投稿・返信も継続動作）。
- 流出refresh_token単体では悪用困難（交換に GBP_CLIENT_SECRET が必要。これはVercel環境変数でanon経由未漏洩）
  → 即時パニック不要と判断し、トークン再発行は後日に。
- 投稿画面の店舗一覧 = Go API /api/shop − 解約店舗(shop-cancel: Supabase shops.cancelled_at IS NOT NULL)。
  ヘッダー検索(header.tsx:20-21)は name.toLowerCase().includes のみでNFKC正規化なし＝全角店名は半角検索でヒットしない。
- create-post(GBPローカル投稿localPosts)は summary 必須。「写真投稿」も内部はtopicType=STANDARDのローカル投稿なので
  本文キャプションは必須（GBP仕様）。キャプション不要の写真だけ載せたい場合は別API(メディア/写真アップロード)が必要。
- Sandbox から *.supabase.co へは到達不可（curl HTTP 000）。外形確認はユーザー側/ダッシュボードで行う。
- git remote: 本番は origin（github: aichubbysystem-sponavi/new-sponavi）、omni は別リポジトリ。main直pushでVercel自動デプロイ。

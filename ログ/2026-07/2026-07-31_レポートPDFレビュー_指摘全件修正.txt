### 発見した不具合（重大度順）

■【最重大】圏外/未計測への転落を「順位改善」として表示していた
- 症状: 「一社 イタリアン」4月1位→6月データなし で 変動「↑6」（緑・上昇）
        多地点でも 4月8.3→6月データなし で「↑6.2」（緑）
        「名東区 パスタ」は「→」（横ばい）
        一方P6のカードは同じKWを「圏外」＋赤↓ → 同一レポート内で結論が真逆
- 真因: client.tsx で null（データなし）を除外してから配列末尾2件を比較していた
        ranks=[3,7,null,1,null] → 除外後[3,7,1] → 2月(7位)と4月(1位)の差=6 を
        「当月の変動」として表示。当月がデータなしでも過去2ヶ月の差分が出てしまう
- 該当4箇所（すべて同じパターン）:
    P7 順位推移テーブル / P8 多地点サマリー右表 / KW別スライドの月別表 / PDF生成側の平均順位
- 対策: report-utils.ts に rankTrend() を新設。必ず「最新列」を基準にし、
        比較相手だけを過去へ遡って探す。4箇所すべてを置き換え。
        旧 avgRankDiff() は隣接2値しか見られず未計測を表現できないため @deprecated に。

■「圏外」と「未計測」を区別できていなかった（上記の派生）
- ranking-fetch.ts の parseRanksHistory / parseRanksHistorySheet3 が
  セル「圏外」も空欄も同じ null に潰していたため、区別不能だった
- 対策: RankHistoryData / RankingHistory の datasets に outOfRange?: boolean[] を追加
        （既存フィールドは変更しないので他の消費側に影響なし）。
        mergeHistories・対象月トリムでも引き継ぐ。
        client側の measured 判定 = グリッド計測あり OR シートが明示的に「圏外」
- 表示: 計測済みで順位なし→「圏外へ」（赤）／未計測→「未計測」（灰・矢印なし）

■ 平均順位が圏外を分母から除外していた
- avgRank は report-api.ts / spreadsheet.ts で results.filter(r=>r.rank>0) の平均。
  → 名東区カフェは49地点中45地点が圏外でも「平均26.5位」と表示され実態を誤認させる
- 対策: rankCoverage() を新設し、圏内率（16/49 等）を
        サマリー表・KW別スライド・PDF地図スライドすべてに併記。50%未満は赤で強調

■ 前年比が計測開始前の断片データで計算されていた
- 対策開始2025年8月／前年同月2025/6は マップ0件・検索4件しかない
  → 「+116325.0%（4→4,657）」「+108,951（0→108,951）」と表示
- 対策: isYoyComparable(yoyValue, curLabel, startDate) を新設。
        前年同月が対策開始月より前、または0以下なら前年比バッジを出さず
        「前年比 なし（前年は計測前）」と理由を書く。
        検索語句テーブルの「前年」「前年比」列も同条件＋共通語句なしで列ごと非表示に
        （PDFでは全行「-」の空列が2列出ていた）

■ データなしKWの地図が真っ白なスライドで出ていた（P11/P12）
- 真因: PDF生成ループが gr.keywords 全件ぶんスロットを作るが、
        対象月のスナップショットが無いと if ブロックごとスキップされ
        プレースホルダ（空の箱＋「平均順位: -位」）が残る
- 対策: 対象月に results があるKWだけを pdfKwEntries に絞ってスライド生成。
        キャプチャループも同じ配列を回し、slotIdx（スロット順）と kwIdx（web側の元index）を分離。
        ページ番号は既存の pageShift 計算がそのまま吸収する（KW0件でも -1 で整合）

■ Googleマップの帰属表示が切れていた（P9〜P12全マップ）
- 左下のGoogleロゴが弧だけ、右下「地図の誤りを報告する」が半分に切れて写り込み
- 対策: html2canvasだと確実に描画できないため、.gm-style-cc / ロゴを一旦隠してキャプチャし、
        マーカーと同じCanvas 2D直描画で「地図データ ©YYYY Google」を右下に描く
        （既存ナレッジ「Google Maps SVGマーカーはCanvas 2Dで直接描画」と同じ方針）

■ AI総評の誤り
- 言語比率「各1〜2%」← 実際0.9/0.9/0.5%。真因は analyze/route.ts の Math.round で
  2/218=0.92%→「1%」、1/218=0.46%→「0%」に潰していたこと。10%未満は小数1桁で渡すよう修正
- 競合「リスト2位以内の2店に次ぐ位置」← 口コミ数順位をAIに数えさせていたため非文になった。
  「口コミ数の順位: N店中M位（検索順位とは別物）」を確定値でプロンプトに渡す
- 「トップとの差は約84件まで縮まっている」← 1時点しかないのに推移を断定。
  プロンプトに「前回値が無いので推移の断定は禁止」を追加
- 口コミ総評がアクション率の話になっていた ← summary は口コミ限定ではなく当月全体の総評フィールド。
  見出しを「口コミ評価と今月の総評」に変更（実態に合わせた）

### 注意点・ハマったこと
- JSXの三項演算子の分岐内に {/* */} コメントを置くとパースエラーになる（要素が2つになるため）。
  /* */ だけにするか要素の内側に置く
- Tailwind preflight が ol/ul の list-style を none にするため、レポートのように
  素のstyleで組んだ箇所は listStyleType を明示しないと箇条書き記号が一切出ない
- PDF生成のKW絞り込みでは「スライド枠の順（slotIdx）」と「web側スライドのindex（kwIdx）」が
  別物になる。setGridKwIdx には元indexを渡さないと違うKWの地図をキャプチャする
- PDF生成で「地図は月セレクタの選択月・平均順位は最新月」という既存の不整合があった（同時に修正）
- avgRank は圏内地点のみの平均という仕様は report-api.ts(121,147) と spreadsheet.ts(499) の
  3箇所に同じロジックがある。変えるならこの3箇所セット（今回は表示側に圏内率を足す方針にした）

#### CSP 'unsafe-inline' の現状
- script-src: 'unsafe-inline' あり → XSS緩和が無効
- style-src: 'unsafe-inline' あり → Tailwind CSS/Next.jsが依存、排除困難
- Next.js 14でnonce実装 → nonce自体のXSS脆弱性(GHSA-ffhc)があるため逆にリスク増
- 結論: Next.js 15アップグレード後にnonce実装するのが唯一安全な方法

### Next.js 15 アップグレード計画

#### 前提
- 現在: Next.js 14.2.35（App Router）
- 目標: Next.js 15.5.x（最新安定版）
- 14→15の破壊的変更が多数あるため、専用セッションで実施

#### 主な破壊的変更（事前調査必要）
1. **React 19 必須** — React 18→19のアップグレードが同時に必要
2. **async Request APIs** — headers(), cookies(), params, searchParams が非同期に
   - layout.tsx の headers() 呼び出し（行20）が影響
   - 全ページでparamsの扱いが変わる可能性
3. **fetch キャッシュデフォルト変更** — no-store がデフォルトに
   - 現在 cache: "no-store" を明示している箇所は変更不要
   - 明示していない箇所のキャッシュ動作が変わる
4. **next/image の変更** — 一部プロパティ廃止
5. **Middleware の変更** — geo, ip プロパティ廃止

#### 作業見積もり
1. package.json 更新 + npm install: 30分
2. TypeScriptエラー修正（async API対応）: 2-4時間
3. 全画面動作確認: 2-3時間
4. nonce実装（CSP unsafe-inline排除）: 1-2時間
5. バッファ: 2時間
- 合計: 約1-2日

#### 進め方
1. git branch next15-upgrade で別ブランチ作成
2. npm install next@15 react@19 react-dom@19
3. ビルドエラーを1つずつ修正
4. ローカルで全画面動作確認
5. CSP nonce実装
6. mainにマージ → デプロイ

#### 注意
- アップグレード中は本番デプロイしない（mainブランチは触らない）
- eslint-config-nextも15系に上げる必要あり
- Prisma等のORM互換性は問題なし（Prisma未使用、Supabase直接）

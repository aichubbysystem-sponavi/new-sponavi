現状は投稿管理 > Step1「店舗を選んで投稿」で、702店舗のリストから
Ctrl+Fで1件ずつ探してチェックを入れている。件数が増えると時間がかかる。
→ 貼り付け＋Enterで自動チェック、見つからない店舗は教えてほしい。

  - 投稿フォーム内「系列店にも同時投稿」にも同じ貼り付けUIを追加

## 照合ポリシー（誤チェック事故を防ぐため段階を分けた）
1. 完全一致（NFKC + 小文字化 + 空白除去）        → 自動チェック
2. 記号無視の完全一致（括弧・中黒等を除去）      → 自動チェック
3. 1/2で候補が複数（同名店舗）                   → 自動チェックせず「要確認」
4. 一致なし                                      → 「未検出」。類似候補は提示するが自動チェックしない
※ 部分一致では絶対に自動チェックしない。
   実データ確認: 370店舗中3件（'CHILLRI' 等）が他店舗名の部分文字列になっており、
   部分一致で自動チェックすると別店舗を巻き込む。

## 実データでの精度検証
sql/2026-08-01_rpa_sheet_shop_check.sql の店舗名370件を店舗マスタ代わりに使用し、
LINEで実際に送られてきた20店舗を照合した結果:
  完全一致 20 / 記号無視一致 0 / 部分一致 0 / 未検出 0  → 20/20 (100%)
また同リスト370件について
  - 正規化（空白除去+小文字化）後の名前重複: 0件
  - 記号除去後の名前重複: 0件
→ 現状のデータでは1〜2の段階だけで一意に決まる。3の分岐は保険。

## UI仕様
- テキストエリアに複数行貼り付け → その場で自動照合（onPasteで実行）
- Enter = 照合実行 / Shift+Enter = 改行（IME変換中のEnterは無視）
- 既定は「置き換え」（貼り付けた店舗だけが選択される）。
  チェックボックス「既存の選択に追加する」で追加モードに変更可
- 結果を 一致N件 / 要確認N件 / 未検出N件 / 重複行N件 でバッジ表示
- 未検出・要確認はボタンで1件ずつ手動チェック可（「もしかして」候補付き）
- 行頭の「・」「1.」「- 」等、全角空白、空行、重複行は自動で処理

追記: GBP改名店舗が未検出になる問題（同日・本番で発覚）

## 症状
本番で20店舗を貼り付けたところ「一致19件 / 未検出1件」。
未検出は「ジェルネイル専門 WHITE NAIL 高崎店」。
候補には栄店・難波店・名駅店・西宮北口店・武蔵小杉店が出たが高崎店が無い。

## 原因（2026-08-08の設計判断の帰結。ロジックのバグではない）
この店舗はアイブロウ店→ネイル店に業態変更してGBP名だけ変わっている。
  shops.name          = アイブロウサロンWHITE EYE まつ毛と眉毛の専門店 高崎店 ホワイトアイ
  shops.gbp_shop_name = ジェルネイル専門 WHITE NAIL 高崎店
shops.name は結合キーなのでGBPの改名に追従しない（2026-08-08で決定）。
一方、投稿画面の shops は Go APIの /api/shop 由来で name しか持たない
（/api/shop は gbp_shop_name / state / city / phone を返さない）。
→ 現場が使うGBP現在名では引けなかった。該当は本番で約29件。

なぜローカル検証で気づけなかったか:
照合テストに使った sql/2026-08-01_rpa_sheet_shop_check.sql は
「口コミRPAシートのA列」であって shops.name ではない。
シート側は既にGBP新名に直されていたため、name と一致する前提が崩れていた。
→ 店舗名の照合を検証するときは shops.name そのものを使うこと。

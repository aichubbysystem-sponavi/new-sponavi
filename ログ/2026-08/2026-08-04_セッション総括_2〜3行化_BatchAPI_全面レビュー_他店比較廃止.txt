### 数値・設定値
- AI総評: 2〜3文 / 合計100〜180字（reviewComments・actionsは従来通り20〜35字）
- max_tokens: 4096 → **8192**
- 計測距離の選択肢: 500m / 1km / 1.5km / 2km / 2.5km / 3km / 4km（**5km廃止**、既定500m）
- gridFactor: `Math.min(0.5, Math.max(0.25, intervalM/1000))` → 実質**定数0.5＝格子約500m**
  （clampの形は将来250m刻みを足したときの保険として残置。下限0.25=250m格子）
- 距離刻みの衝突確率（実測4000サンプル・斜め配置で5地点が完全一致する確率）:
  **500m⇔1km 1.5% / 1.5km⇔2km 2.6% / 2.5km⇔3km 0.6%**（他ペアは0.5%未満）
- Batch: MAX_CORRECTIONS=2 / LOCK_TTL=6分 / MAX_POLL_ATTEMPTS=20 / 1回のpollで最大5バッチ
- クライアントtimeout（一括計測）: 15秒 → **60秒**（サーバmaxDuration 300秒より短いと二重課金）
- 1店舗あたりの原価: 通常 **¥50〜70** / 理論上の最大 **¥175**
  （Places API ¥120 + AI総評 ¥45 + 競合比較 ¥5 + P-MAXまとめ ¥4）
  Batch化が実運用に乗れば AI総評が半額になり最大 **¥140前後**
- 牛草シート: 371店中 **366店**をAU/AV記入（DB349店 / Places API 17店）。Places API実費 約¥850

### 注意点・ハマったこと
- **プロンプトの出力例が実在店舗の実データだと事故る**: 旧例が patty rôti の実KW名で
  「一社 イタリアン/名東区 パスタが1位から圏外に転落」と書かれており、その店の生成時に
  例文と実データが混同されてP6の状態取り違えが起きた。例は必ず架空にし「例は架空」と明記する
- **AIにデータを渡さないだけでは足りない**: 他店平均を渡さなくても「平均を上回る」と推測で
  書くことがある。禁止をプロンプトに明文化して初めて消える
- **照合ゲートの判定順**: 予防表現（「転落しないよう」）の除外を後ろに置くと、
  不在主張の alternation「ない」に部分一致して正しい文が違反になる。除外は必ず先に評価する
- **Batchは投入〜取込の約1時間、DBに痕跡が出ない**: そのため「押したか不安→リロード→再クリック」
  で全店二重投入になりうる。pendingチェックが無いと課金が倍になる
- **クライアントtimeout < サーバmaxDuration は二重課金の温床**: サーバがまだ処理中なのに
  クライアントが諦めて再送すると、同じ地点・同じプロンプトで二重に課金される
- **Mapsの口コミ件数はヘッドレスブラウザで取得できない**: 自動化検知で簡易レイアウトが返り、
  評価(4.3)は取れるが件数が描画されない。静的HTML・embedにも数値は入っていない
  → 公式値が必要なら Places API（Pro単価¥4.8）しかない
- **DB集計の口コミ件数はGoogle公式表示と一致しない**: Googleで削除された口コミがDBに残るため
  DBの方が数件〜十数件多い（逆に同期漏れで少ない店もある）。評価は±0.1以内で一致する
- **business_group_id は全608店が自社**（未設定ゼロ）。「グループ平均」は系列店の平均ではなく
  焼肉店も脱毛サロンも混ざった全店平均だった
- **gridFactorは実質定数**: 許可インターバルが500m以上なので intervalM/1000 は常に0.5以上。
  「距離に比例」というコメントは実態と合っていなかったため修正済み
- レビューエージェントの指摘も鵜呑みにしない: 「500m⇔1kmの衝突29%」は実測1.5%で過大、
  「月平均の全角表記が誤検知」はテストで正常動作を確認して却下した

### 注意点・ハマったこと
- 本番DBへの直結は自動モードでブロックされる。読み取りは scratchpad の q.py をユーザーが `!` で実行する運用。ローカル .env.local は別プロジェクト（rtqvyuscibswachlewks・DNS不可）で本番ではない
- 「店舗が見つからない」の真因は deleted_at（論理削除）。Go API /api/shop は削除済みを返さず、GBP連携は残るので「連携済みなのに一覧に居ない」状態になる。削除・解約の店舗数は 795−72−4=719 のように画面件数から逆算できる
- 「写真なし」の真因: (1) 店舗フォルダ名の先頭管理番号「202 …」で完全一致に失敗 (2) .arw（Sony RAW）等の非対応形式 — 以前のメッセージは「マッチ0件・例: スクリーンショット…」で判別不能だった
- GBPの400はAPI応答を200文字で切って保存していたため errorDetails（本当の理由）が消えていた。全文を持って日本語化すること
- 再実行/今すぐ実行経路は Media API に mediaFormat:"PHOTO" 固定で送っていた（動画は必ず400）。cron経路だけ正しかった
- クライアント290秒タイムアウト後の再送と、まだ走る旧リクエストで同一予約が2本できる → select→insert では防げず、DB制約が必要
- 「重複スキップ」を再実行対象に含めると永久に未完了になる（1回目レビュー対応で自分が作った副作用）
- /code-review の本体エージェントはサブ検証の通知待ちで止まることがある。tasks/*.output から最終テキストを直接回収すれば結果は取れる（cp932 で落ちるので PYTHONIOENCODING=utf-8）
- Shift-JIS CSV を UTF-8 として取り込むと名前が U+FFFD+英数バイト残骸になる（04-14 の PICASSO 文字化け行）。hex で見れば判別できる
- 4月に GBP同期が店名照合に失敗して正式名で別行を作っていた（8/8 の gbp_shop_name 追従以前）。同じロケーションに2行できたら統合スクリプトで寄せる
- Vercel は origin main への push で自動デプロイ。Deployments に新コミットが出なければ未push

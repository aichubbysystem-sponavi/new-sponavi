### 注意点・ハマったこと
- **本番 shops に rating/review_count 列が存在しなかった**。sync-reviews は以前から `shops.update({rating, review_count, gbp_full_path, gbp_location_name})` を投げており、列が無いため update が**まるごと黙って失敗**していた（= gbp_full_path の永続化も効いていなかった）。analyze/route.ts に「shopsにrating列は無い」というコメントが残っていたのが手掛かり。shop-ratings / rpa-sheet-check API も同じ理由で動いていなかったはず
- 16万件超の reviews を「全件OFFSETページング」「店舗ごと8並列」のどちらで引き抜いても statement timeout。authenticator の 8s 制限はクエリ単位なので合計で超えるとダメ。結局、実行時点の掲載値（shops）を使う要件に変わったため回避
- /api/export は先頭で `month=YYYY-MM` を全typeに強制検証していた。新typeを足す時は month の扱いを最初に見ること
- Vercel CLI（.vercel/）は死んだ重複プロジェクトを指しており `vercel ls` の Error 一覧は本番と無関係。反映確認は本番URLのJSバンドルに新文言が含まれるかで判定
- **CSVのファイル名を参考ファイルと同名（【RPA】MEOレポート用 - 202607.csv）にしたため、ユーザーの参考ファイルが Downloads で上書きされて消えた**。見本と同名は絶対に避ける
- threshold 語句を count に含める変更は、count を合計する消費側（AI分析の総検索数・指名検索比率）を壊す回帰だった。同期データの意味を変えたら必ず消費側を grep する
- Python heredoc で `\uFEFF` `\r\n` をTS文字列に書き込むと Bash 側で実エスケープに化ける。chr(92) で組み立てるか、ファイルのCRLF/LF を確認してから byte 置換する
- 参考CSV突合: 8店舗×上位7位で語順・件数一致。差は1位の大きい値のみ（シートが概算丸め）

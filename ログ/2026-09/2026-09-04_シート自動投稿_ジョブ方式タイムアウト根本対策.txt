2026-09-04 シート自動投稿 タイムアウト根本対策（ジョブ方式へ移行）
=====================================================================

■ 発端
- 投稿管理・分析 →「シートから自動投稿」→「自動投稿を実行」で 80店舗の写真投稿を即時実行。
- 画面表示: 「1回目完了: 0件投稿 / 1件エラー」「バッチ1 通信エラー: timeout of 180000ms exceeded」
  「2回目: 未完了0件を実行」
- 原因（コード確認済み）
  1. 即時投稿はブラウザが10店舗ずつ /api/report/auto-post を呼び、1リクエスト上限180秒。
     10店舗×3枚=30ファイルの Dropbox→Storage 転送＋GBP Media API は直列で3分を超える。
  2. 通信エラー時はループ中断（hasMore=false）→ 残り70店舗は一切送られない。
  3. 通信エラーは「バッチ1」という擬似行で記録され、再実行対象（店舗名）が0件になる。
     0件だと buildAutoPostFilter が Step1 の選択（80店舗全体）に戻るため、
     「2回目」を押すとバッチ1で成功済みの店舗に同じ写真を二重投稿する状態だった（写真投稿に重複チェックなし）。
  4. サーバー側（maxDuration 300秒）はクライアント切断後も走り続けるため、バッチ1の投稿は裏で成立している可能性あり。
- 今後 300店舗を一気に流す予定 → 「ブラウザが長い通信を待つ」構造そのものを廃止。

■ 新方式（ジョブ方式）
  画面 ──POST /api/report/auto-post-jobs（数秒）──▶ auto_post_jobs に1件登録 ──kick──▶ /api/cron/auto-post-worker
                                                                                          │ 店舗名リストを5店舗ずつ runAutoPost（予約登録と同じ処理）
                                                                                          │ 結果を auto_post_job_items、進捗を cursor に保存
                                                                                          │ 180秒で新規スライスをやめ、残りがあれば自分を再起動
  画面 ◀──GET ?id=（4秒ごとポーリング）── 進捗バー・結果一覧・中止ボタン。タブを閉じても処理は続き、開き直せば復元
  保険: vercel.json に auto-post-worker の毎分 cron を追加（queued／lease期限切れの running を拾う）

  mode
  - check     事前チェック（登録しない）
  - schedule  予約投稿として登録
  - immediate 即時投稿 ＝「今」の予約として登録し、cron/execute-posts が数分以内に順次GBPへ公開。
              以前の「ブラウザの1リクエスト内でGBPへ直接投稿」経路は画面から使わない（engine には残置・互換用）。
              警告あり（CTAリンク異常等）は予約と同じく保留になる。写真投稿に警告は発生しない。
  - 同時に1ジョブのみ（2本目は409）。中止は PATCH action=cancel（処理中スライス終了後に停止）。

■ 本番反映と実動作（同日）
  - SQL 適用済み → 71b6a40 push → 事前チェック72店舗（74選択）を約10分で完走（10店舗/約1分）。
    結果: 登録可能131枚 / 登録不可28店舗（写真ファイルなし17・Dropboxフォルダなし11）
  - 続けて即時投稿を実行 → 「完了: 131件登録 / 28件スキップ」。登録時スキップ一覧に28件の理由が残っている
  - ユーザー指摘: 80店舗中4店舗（カネマス弥平とうふ店／アイブロウサロン WHITE EYE 小倉／アイブロウ専門店iBROW.浜松駅前店／
    ホワイトニングショップ栃木佐野店）が結果にもスキップ一覧にも出ない
    → 原因: Step1で選んでもシートB列に一致しない店舗はプレビューの母数から黙って減る構造だった（74選択→72マッチ）。
      Step1の貼り付けで店舗マスタに無い名前は「見つからなかった店舗」に出るが、シート側の不一致は表示が無かった
    → 対処（7884392）: engine が unmatchedFilterNames を返し、画面に「Step1で選んだのにシートに見つからない店舗」を
      一覧表示＋確認ダイアログに件数。4店舗の具体的な原因（B列表記ゆれ or 日付行なし）はデプロイ後にこの一覧で確認する
  - シート本体はローカルのGoogleトークン・Playwrightとも403で読めない（アプリはGBP用OAuthトークンで読んでいる）
